# ORust Phase 3: Modules, imports, show/hide, export

Read AGENTS.md first. All hard rules still apply (rustc is the source of truth, errors shown in .or terms, nothing hidden by default). This phase adds a Dart-style module system that compiles to Rust's module and visibility system. Continue numbering from the last milestone (start at 15 if Phase 2 is done).

## Goal
A developer can split a project across many `.or` files, control exactly what each file shows to the others, and have the result map cleanly onto Rust modules and `pub`. Plain `.rs` files in the same project can use exported ORust items, and ORust can import Rust files and crates. Users never write `mod`, `pub`, `pub(crate)`, or `use`.

## Visibility model
Everything is **file-private by default**. `export` is what makes something visible to other files.

| ORust | Emitted Rust |
|---|---|
| `class Foo { }` (no modifier) | `struct Foo` (private to the module) |
| `export class Foo { }` | `pub struct Foo`, with `pub fn new`, plus `pub` fields and `pub fn` methods for every member NOT marked `private` |
| `export interface Speak { }` | `pub trait Speak` (trait methods are always pub) |
| `export enum Shape { }` | `pub enum Shape` |
| `export void helper() { }` | `pub fn helper()` |
| `export const int max = 10;` | `pub const MAX: i32 = 10;` |
| `private` member inside an exported class | no `pub` (hidden from other files) |
| `internal` (on a top-level item or member) | `pub(crate)`, visible to the whole package, not to outside crates |
| `export shared class Foo { }` | `pub` type alias and `pub` data struct, with the Rc/RefCell wrapping still handled by the compiler |

Rules:
- `export class` exports the class and all its members except those marked `private` or `internal`. Members cannot be exported from a class that is not exported; give a friendly error ("export the class first").
- Plain `class Foo` can still have `private` members; this is allowed and changes nothing, since the class is already file-private.
- If an exported item's public signature mentions a file-private type, error with the friendly translation of rustc's private-type-in-public-interface diagnostics (E0446 / `private_interfaces` lint, which we treat as an error): "`User.friend()` is visible to other files but returns `Helper`, which is private to this file. Add `export` to Helper, or mark the method `private`."
- `show`, `hide`, `as`, `export`, `private`, `internal` are **contextual keywords**: they are only keywords in the positions below, so existing identifiers named `show` etc. keep working.

## Directives
```
import 'models/user.or';                       // everything exported by user.or
import 'models/user.or' show User, Admin;      // only these names
import 'models/shapes.or' hide Square;         // everything except Square
import 'utils/strings.or' as strings;          // namespaced: strings.shout("x")
import 'utils/strings.or' as s show shout;     // namespace + filter

export 'models/user.or';                       // re-export all of user.or's exports
export 'models/user.or' show User;             // re-export selected names
export 'models/shapes.or' hide Square;         // re-export all except Square
```
The word `export` is used two ways, distinguished by position: before a string literal it is a re-export directive, before a declaration it is a visibility modifier.

### Path forms
- Relative: `'user.or'`, `'./user.or'`, `'../shared/x.or'`
- Package root: `'package:myapp/models/user.or'` (the name comes from `orust.toml`)
- Other ORust package (dependency in `orust.toml`): `'package:otherlib/otherlib.or'`
- Rust crate: `'rust:serde_json' show Value, json;`, `'rust:std/collections' show HashMap;`
- Local plain Rust file: `'rust:./helpers.rs' show parse_line;`

### Semantics to implement
- Imports are **not transitive**: importing a file does not give you what that file imported. Only `export` directives re-export.
- Default imports (no `show`) bring in every exported name. Emit an **explicit `use` list**, never a glob `use x::*`. This makes `hide` trivial (filter the list at compile time), makes collisions detectable, and gives better error messages.
- `as name` emits `use crate::path::to::file as name;` and rewrites `name.Foo` to `name::Foo` (and `name.helper()` to `name::helper()`).
- Two imports bringing the same name into one file is an error unless disambiguated with `show`, `hide`, or `as`. Friendly message: "`Shape` comes from both `a.or` and `b.or`. Use `hide Shape` on one import, or `as` to give one a prefix."
- Unused imports produce a warning. Importing a name that the target file does not export is a friendly error (see diagnostics).
- Circular imports between files in the same package are allowed (Rust permits it). Do not try to forbid them. Rely on rustc for any real problem.
- **Auto trait imports (important):** in Rust a trait must be in scope to call its methods. If `Dog` is imported from file A and implements interface `Speak` defined in file B, a call to `dog.speak()` needs `Speak` in scope. The compiler must automatically add `use path::Speak as _;` for every exported interface implemented by any imported class (and for every interface of an imported interface-typed value). Users should never have to `show` an interface just to call its methods.

## Module mapping
- Each `.or` file becomes a Rust module. Directories become parent modules. The generated cargo project mirrors the source tree under `target/orust/<pkg>/src/`.
- The entry file (`main.or` for a binary, `lib.or` for a library) becomes `main.rs` / `lib.rs`, with `pub mod` declarations generated for all reachable files (users never write them). A directory with an `index.or` file uses it as that directory's barrel (the file that holds its re-exports); otherwise a `mod.rs` is generated.
- File and directory names map to snake_case module names. Names that are Rust keywords get an `r#` prefix automatically.
- Naming bridge: ORust `camelCase` members emit as `snake_case` Rust (`getUser` becomes `get_user`); types stay `PascalCase`; constants become `SCREAMING_SNAKE`. Provide `@rustName("exact_name")` to override. This mapping is **stable and documented** (docs/naming.md) because plain Rust files depend on it.
- Package config `orust.toml`:
```
[package]
name = "myapp"
version = "0.1.0"
entry = "main.or"          # or lib.or for a library

[dependencies]
otherlib = { path = "../otherlib" }      # ORust package
serde_json = "1"                         # Rust crate, passed through to Cargo.toml
```

## Rust interop (both directions)
- **Rust uses ORust:** `orust build --lib` emits a normal cargo library crate. Anything `export`ed is `pub` with the naming bridge above, so a plain `.rs` file in the same project can write `use crate::models::user::User;` and call `user.get_name()`.
- **Mixed projects:** `.rs` files inside the source tree are copied through to the generated tree unchanged and added to the module tree. Span mapping for them is the identity (errors in `.rs` files are shown as plain rustc errors, since they are Rust).
- **ORust uses Rust:** `import 'rust:...'` as above. Imported Rust items are untyped from ORust's point of view at first. For v1, require the user to rely on rustc to check usage (do not parse Rust signatures). Document this limitation in docs/modules.md.

## Example that must work (milestone 17 acceptance)

`models/user.or`
```
export class User {
  String name = "";
  int age = 0;
  private String secret = "";
  String greet() { return "hi $name"; }
  private void audit() { }
}

export interface Describable {
  String describe();
}

class Helper { }          // file-private
```

`models/shapes.or`
```
export class Circle { double r = 1.0; }
export class Square { double side = 1.0; }
```

`utils/strings.or`
```
export String shout(String s) { return s.toUpperCase(); }
```

`models/index.or`
```
export 'user.or' show User, Describable;
export 'shapes.or' hide Square;
```

`main.or`
```
import 'models/index.or';                 // User, Describable, Circle
import 'utils/strings.or' as strings;

void main() {
  var u = new User();
  u.name = "ada";
  print(strings.shout(u.greet()));
  var c = new Circle();
}
```

Expected emitted Rust shape:
```rust
// models/user.rs
pub struct User { pub name: String, pub age: i32, secret: String }
impl User {
    pub fn new() -> Self { User { name: String::new(), age: 0, secret: String::new() } }
    pub fn greet(&self) -> String { format!("hi {}", self.name) }
    fn audit(&self) {}
}
pub trait Describable { fn describe(&self) -> String; }
struct Helper;

// models/shapes.rs
pub struct Circle { pub r: f64 }
pub struct Square { pub side: f64 }

// models/mod.rs
pub mod user;
pub mod shapes;
pub use user::{User, Describable};
pub use shapes::Circle;

// utils/strings.rs
pub fn shout(s: String) -> String { s.to_uppercase() }

// main.rs
mod models;
mod utils;
use models::{User, Describable, Circle};
use utils::strings;
fn main() {
    let mut u = User::new();
    u.name = String::from("ada");
    println!("{}", strings::shout(u.greet()));
    let c = Circle::new();
}
```
Negative tests that must produce friendly errors: using `Helper`, `Square`, `u.secret`, or `u.audit()` from `main.or`.

## Diagnostics (extend the error translator; all must show .or lines from the correct FILE)
The span table and diagnostics plumbing must now be **multi-file**: every span carries a file id, and errors print the correct `.or` path.

| rustc code | Friendly translation |
|---|---|
| E0432 unresolved import | "`models/user.or` has no export named `Admin`. Check the spelling, or add `export` to it in that file." (list what that file DOES export) |
| E0433 failed to resolve path / unknown namespace | "I don't know `strings`. Did you forget `import 'utils/strings.or' as strings;`?" |
| E0603 item is private | "`Helper` is private to `user.or`. Add `export` before it there if other files should use it." |
| E0616 field is private | "`secret` is private to `User`. It was marked `private` in user.or. Remove `private` or add a method that exposes it." |
| E0624 method is private | "`audit()` is private to `User` and can't be called from this file." |
| E0252 / E0254 / E0255 name defined multiple times | collision message with `show` / `hide` / `as` fixes |
| E0412 unknown type, E0425 unknown value | if the name exists in an exported-but-not-imported file, suggest the exact `import` line |
| E0446 / private_interfaces | message in the "Rules" section above |
| unused import (warning) | "`import 'x.or'` is never used" |

"Did you mean" help: when a name is not found but some file in the package exports it, suggest `import 'path' show Name;` with the shortest correct relative path.

## Testing
- Golden tests now use **directories**: `tests/projects/<name>/` containing the `.or` tree, `orust.toml`, expected `emit/` Rust tree, and `expected.err` for negative cases.
- Every directive form in this prompt (each import/export variant, each path form that does not need the network) becomes a test.
- One negative test per diagnostic in the table above, with expected friendly output including the correct file path.
- E2E: build and run the acceptance project and assert stdout.
- Test that `hide` of a name that the target does not export is a warning, not a hard failure, and that `show` of a missing name is an error.
- Test the auto trait import: calling an interface method on an imported class when only the class was shown.

## Working rules
- Same as AGENTS.md: do not stop to ask questions, choose the simplest option that fits the core principle, log choices in `docs/decisions.md`.
- Never reimplement Rust's privacy checking. We generate `pub` / non-`pub` correctly and rustc enforces it; we only translate its errors. The one check we do ourselves is "member of a non-exported class marked export" because rustc cannot see that intent.
- If a feature would require parsing Rust signatures (importing Rust items with full type info), emit a "not supported yet" note and rely on rustc instead.
