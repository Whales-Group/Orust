## Goal
Any Rust attribute, from the language or from any crate, can be written in ORust as an annotation and reaches rustc as the equivalent `#[...]`, with ORust knowing nothing about any crate's semantics. ORust does only three things: translate the syntax, put the attribute on the right generated Rust item, and translate the errors that come back. This is a purely syntactic bridge. There is no per-crate knowledge, no annotation "packs", and no schema for arguments.

## Hard rules for this phase
1. **Syntactic translation only.** ORust never interprets an attribute's meaning. If a crate defines `#[foo(bar = 1)]`, `@foo(bar: 1)` just works without ORust ever hearing about `foo`.
2. **String contents are sacred.** Never rewrite what is inside a string literal, except converting escape sequences to their Rust equivalents. Strings in annotation arguments are NEVER interpolated: `$` is a literal dollar sign there.
3. **Argument identifiers are never renamed.** The naming bridge (`camelCase` to `snake_case`) does not apply inside annotation arguments. Users write the Rust name where an argument refers to a Rust item. (A lint helps; see OR0654.)
4. **Every emitted attribute is traceable to its `.or` source, down to individual argument tokens.**
5. **Restricted attributes need an explicit opt-in** (list below). Everything else is allowed by default.
6. **Deterministic output.** Same input, byte-identical attributes, in a documented order.
7. **Rust is the judge.** Do not pre-validate target legality (for example "derive on a method") or argument spelling; rustc already does. Translate its errors instead.

## Surface syntax
```
annotation  := '@' ['!'] path [ '(' tokens ')' | '=' literal ]
path        := ident { ('.' | '::') ident }
```
- `@` must be immediately followed by the name (no space) and `(` must immediately follow the name when arguments are given (no space), because `(int, String) x` is a valid declaration start. Stacked annotations may be on one line or separate lines, and may be separated from the declaration by newlines and comments.
- `@!name(...)` is an inner (file-level) annotation, emitted as `#![...]`. It must appear before the first declaration (after the shebang, license header, and `//!` docs). Elsewhere: `OR0652`.
- `@name = "text"` emits `#[name = "text"]`. This is how `@must_use = "check the result"` and `@doc = "..."` work, because Rust's `#[must_use("...")]` is not valid. **The shape of an attribute is Rust's shape; ORust only changes punctuation.** Document this prominently.
- `@rust("serde(with = \"my_mod\")")` is the raw escape hatch: the string is the attribute body verbatim. `@!rust("...")` is the inner form. Validate only that delimiters balance (OR0655 otherwise); let rustc judge the rest. Flagged by `orust audit`.
- Doc tags (`@author` inside `///` comments) are unrelated and unchanged (see Phase 6 rule: doc tags only exist inside doc comments).

## Translation rules (token tree to token tree)
Parse the argument list into a token tree (ident, literal, punctuation, delimited group), then emit:

| ORust token pattern | Rust output |
|---|---|
| `ident: value` at the start of an argument (after `(` or `,`) | `ident = value` |
| `ident = value` | unchanged (accepted; formatter normalizes to `:`) |
| `a.b.c` (idents joined by `.` with no spaces) in a path position | `a::b::c` |
| `a::b::c` | unchanged (accepted; formatter normalizes to `.`) |
| `this` (alone) | `self` |
| `this.name` | `self.name` (the `.` stays a field access; a path whose first segment is `this` is not converted) |
| `"text"`, `r"text"`, `r#"text"#`, `"""multi"""` | a Rust string literal with the same value; no interpolation; `\$` becomes `$`; unknown escapes are an error |
| `'x'` (exactly one Unicode scalar or one escape) | Rust **char** literal `'x'` |
| any other single-quoted literal | error: "inside annotations, 'x' is a character; use double quotes for text" |
| numbers (`1_000`, `0xff`, `1.5e3`, suffixes), `true`, `false`, `-1` | unchanged |
| nested groups `()`, `[]`, `{}` | same delimiters, translated recursively |
| operators and punctuation (`|`, `&`, `<`, `>`, `..`, `!`, `,`) | unchanged |
| comments inside the argument list | dropped from the emitted attribute |
| identifiers, keywords, type names, crate names | unchanged, never renamed |

Because `.` becomes `::` between identifiers, field-access expressions inside arguments need the `@rust("...")` escape (except the `this.name` case above). Log the `.`-vs-`::` heuristic in docs/decisions.md and add tests on both sides of it.

## Resolution order for an annotation name
1. ORust-defined annotations keep their meaning: `@data`, `@json`, `@override`, `@rustName`, `@unstable`, and the `@impl.` placement prefix (below). To reach a crate attribute with one of these names, use a path (`@mycrate.data`) or `@rust("data")`.
2. Everything else is passthrough.
There is no import gate for annotations. Derive helper attributes (`serde`, `error`, `from`, `arg`, ...) are introduced by derive macros, not by imports, so ORust cannot know whether a name is legitimate. Instead:
- `@derive(Serialize)` needs `Serialize` in scope in the emitted Rust, so `import 'rust:serde' show Serialize;` (from Phase 3) is how users bring it in, or they write the full path `@derive(serde.Serialize)`.
- A lint, `OR0650 unrecognized annotation`, warns (configurable) when an annotation's first segment is not: a Rust built-in attribute, a name introduced by an import in this file, a crate in `[dependencies]`, a helper name listed in orust.toml `[annotations] helpers = ["error", "from", "source"]`, or a name already used successfully elsewhere in the package. The warning includes did-you-mean suggestions from those sets. It is a lint, not an error, because rustc is the real judge.

## Placement: which generated Rust item gets the attribute
A `class` becomes several Rust items, so placement is explicit and documented in docs/annotations.md:

| ORust target | Rust item that receives the attribute |
|---|---|
| class, shared class (data struct), record | the `struct` (primary item) |
| field | the struct field |
| method, constructor, function | the `fn` (constructor: the generated `new`) |
| interface | the `trait`; interface method: the trait method |
| enum, enum case | the `enum`; the variant |
| `error` type, its cases | the generated struct/enum; its variants |
| top-level `const`, `typedef` | the `const`; the `type` alias |
| `test`, `group` | the `#[test]` fn; the `mod` |
| `var` statement | the `let` statement |
| function parameter | the parameter (Rust allows `cfg` and lint attributes there) |
| `import` | the `use` item |
| `@impl.name(...)` prefix on a class | the **inherent `impl` block** instead of the struct |

Replication rules (all documented and tested):
- **Existence attributes (`cfg`) are replicated on every generated item for the declaration**: struct, inherent impl, trait impls, `Drop` impl, shared-class alias, and any generated helper. A `@cfg(feature: "http") class Client` must disappear completely when the feature is off, not leave an orphan `impl`.
- **Lint-level attributes (`allow`, `warn`, `deny`, `forbid`, `expect`) on a class are replicated on its struct and all its impl blocks**, matching what OOP users expect from "class-wide" suppression. On a method they apply to that fn only.
- Everything else goes only to the primary item (struct, fn, field, ...). An attribute macro on a class therefore sees only the data struct, never the methods; document this and show the `@impl.` workaround. `@impl(Speak).name` (trait impl blocks) is "not supported yet" in v1; log it.
- **Derives:** collect every `@derive(...)` on an item plus compiler-added derives (from `@data`, `shared`, etc.) into ONE `#[derive(...)]`, placed FIRST among the item's attributes (so derive helper attributes always come after it; verify the `legacy_derive_helpers` behavior empirically), preserving first-seen order and removing duplicates (a duplicate derive would cause conflicting-impl errors). Emit an info note on removal, not an error.
- **Everything else is emitted in source order**, after the derive.
- **Duplicates of compiler-generated attributes are suppressed:** if the user writes `@tokio.main` on an `async` main (which the compiler already wraps with `#[tokio::main]`) or `@tokio.test` on a `test async`, emit it once. Same for `@test`/`#[test]` on `test` blocks.
- `@!name` inner annotations go at the top of the module file for that `.or` file. Crate-level-only attributes (`no_std`, `recursion_limit`, `feature`) are only valid in the crate root: rustc will say so; translate it.

## Restricted attributes
These change linking, ABI, crate shape, or break the generated-code assumptions. They are errors (`OR0651`) unless allowed in orust.toml `[annotations] allow_restricted = ["no_mangle", ...]`, and every use appears in `orust audit`:
`no_mangle`, `export_name`, `link_section`, `link`, `link_name`, `used`, `global_allocator`, `panic_handler`, `no_std`, `no_main`, `windows_subsystem`, `proc_macro`, `proc_macro_derive`, `proc_macro_attribute`, `macro_export`, `macro_use`, `path`, `recursion_limit`, `type_length_limit`, `crate_type`, `crate_name`, `feature` (nightly only), `target_feature`, `instruction_set`, `naked`.
- Check nested positions too: `@cfg_attr(x, no_mangle)` is restricted.
- Edition detail: newer Rust editions require `#[unsafe(no_mangle)]`-style syntax for some of these. Verify which attributes and which editions on the CI toolchain, log it, and emit the `unsafe(...)` wrapper automatically when the generated crate's edition requires it.

## Span mapping (extends the span table from milestone 3)
- For every emitted attribute, record the `.or` span of the whole annotation AND of each argument token (key, value, nested group), because translation shifts columns (`rename: "x"` to `rename = "x"`). An error pointing at `renam` inside `#[serde(renam = "x")]` must map to the `renam` token in `@serde(renam: "x")`.
- Macro expansions: rustc diagnostics from derive and attribute macros usually point at the attribute or at the item with an `expansion` chain. Climb the expansion chain to the outermost span in generated code, then map that to the owning annotation or declaration. Identify derive-originated errors by the expansion's macro name (it looks like `#[derive(Clone)]`; verify the exact JSON shape on the CI toolchain with a captured fixture and log it).
- If the span lands in code that has no `.or` origin (macro-generated), fall back to the nearest annotation or declaration and say "this comes from `@derive(Clone)` on `Socket`".

## Diagnostics to translate (in .or terms)
No-code diagnostics need message-pattern matching plus structured fields (as in the rustplain design); confirm each message's exact wording and whether it has a code on the CI toolchain, and capture fixtures.

| rustc says | ORust says |
|---|---|
| cannot find attribute `serd` in this scope (no code) | "there's no annotation `@serd`. Did you mean `@serde`? If it comes from a crate, add the crate to `[dependencies]`." (suggestions from known names) |
| cannot find derive macro `Serialise` in this scope (no code) | "no derive named `Serialise`. Did you mean `Serialize`?" If rustc suggests `use serde::Serialize;`, rewrite to `import 'rust:serde' show Serialize;` |
| derive helper used but crate lacks the feature (for example serde without `derive`) | when the missing name is a derive from a crate in `[dependencies]`, suggest checking the crate's features in orust.toml (generic wording; no per-crate table) |
| E0277 / E0369 / E0599 raised inside a `#[derive(X)]` expansion | "`@derive(Clone)` on `Socket` needs every field to be Clone; `stream` (TcpStream) isn't. Remove the derive, or change that field." Cover Debug, Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord, Default; name the offending field using rustc's own span on the field |
| E0204 Copy on a type with non-Copy field | same shape, naming the field |
| E0774 derive on something that is not a struct or enum | "`@derive` only works on classes, enums, records and errors, not on methods or functions." |
| E0517 / E0518 attribute on wrong item (`repr`, `inline`) | "`@repr` belongs on a class or enum; this is on a method." |
| E0452 / E0453 malformed or overruled lint attribute | explain `@allow`/`@forbid` interplay in plain words |
| E0658 unstable feature, `#![feature]` on stable | "this needs the nightly toolchain; ORust projects target stable by default" |
| macro-reported errors (for example serde's "unknown field attribute") | pass the macro's own message through, shown at the mapped `.or` argument token, prefixed with the annotation name |
| malformed attribute input (no code) | "`@derive` needs a list of names: `@derive(Debug, Clone)`", mapped to the annotation |
| `unexpected_cfgs` warning for a feature name | "`feature: "http"` isn't a feature of this package. Add it to `[features]` in orust.toml." |
| inner attribute not permitted here | "file-level annotations (`@!...`) go at the very top of the file" |
| unused attribute warning | "this annotation has no effect here" |
| E0433 failed to resolve path (`serde::Serialize`, crate missing) | reuse the Phase 3 translation; add "add `serde` to `[dependencies]`" |

## Lints
| Code | Lint | Default |
|---|---|---|
| OR0650 | unrecognized annotation (heuristic, did-you-mean) | warn |
| OR0651 | restricted attribute used without opt-in | error |
| OR0652 | `@!` inner annotation not at the top of the file | error |
| OR0653 | duplicate derive removed (info) | allow |
| OR0654 | a string argument exactly equals an ORust identifier whose Rust name differs (for example `default: "defaultAge"` when the fn is emitted as `default_age`); suggest the Rust name or `@rustName` | warn |
| OR0655 | `@rust("...")` string has unbalanced delimiters | error |
| OR0656 | annotation stands alone with no declaration after it | error |
| OR0657 | `this.x` style or `.`-heuristic ambiguity noticed in arguments (suggest `@rust`) | allow |
Each lint gets a docs entry, an `orust explain` entry with a verified example, and a suppression test (`// orust:allow(OR0650)`).

## Examples that must work (acceptance)

A. Serde (opt-in online test; see Testing)
```
import 'rust:serde' show Serialize, Deserialize;

@derive(Debug, Serialize, Deserialize)
@serde(rename_all: "camelCase")
export class User {
  String firstName;

  @serde(rename: "years", default)
  int? age;

  @serde(skip)
  String cache = "";

  User(this.firstName);
}
```
Expected emitted Rust shape:
```rust
use serde::{Serialize, Deserialize};

#[derive(Debug, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct User {
    pub first_name: String,
    #[serde(rename = "years", default)]
    pub age: Option<i64>,
    #[serde(skip)]
    pub cache: String,
}
impl User {
    pub fn new(first_name: String) -> Self { User { first_name, age: None, cache: String::new() } }
}
```

B. Built-ins only (must run with no extra crates)
```
@!allow(dead_code)

@derive(Clone, Copy, Debug, PartialEq)
@repr(u8)
enum Level { Low, Mid, High }

@cfg(feature: "extras")
class Extras { int n = 0; }

@ignore
test "slow" { expect(true); }

@should_panic(expected: "boom")
test "panics" { fail("boom"); }     // fail() is from milestone 28
```
Expected: `#![allow(dead_code)]` at the top of the file; one merged derive placed before `#[repr(u8)]`; `Extras` struct AND its impl both carry `#[cfg(feature = "extras")]`; `#[ignore]` and `#[should_panic(expected = "boom")]` on the generated `#[test]` fns. `orust test` reports one ignored and one passing test.

C. Placement and replication
```
@allow(unused_variables)
@impl.inline
class Counter {
  int n = 0;
  void inc() { n++; }
}
```
`@allow(unused_variables)` lands on the struct and the inherent impl; `@impl.inline` becomes `#[inline]` on the impl block (rustc will complain it is not valid there; this fixture exists to test the "wrong target" translation E0518 and the span mapping to the `@impl.inline` annotation).

D. Hermetic proc-macro fixtures (these must pass in offline CI)
Create two local crates under `tests/fixtures/crates/` and use them as path dependencies:
- `orust_fixture_derive`: derive macro `Describe` with a helper attribute `describe(name = "...", skip)` that generates `fn describe() -> String`.
- `orust_fixture_attr`: attribute macro `trace(label = "...")` that wraps a function body with enter/exit `println!`s.
Write them with only `proc_macro` (no `syn`/`quote`) or with vendored copies checked in, so the tests need no network. Programs exercise: derive plus helper attribute with a `key: value` pair, an attribute macro on a method, a macro that emits an error at a specific argument token (a `Describe` helper given an unknown key) and the expected mapping to that `.or` token, and an attribute macro placed on a class (sees only the struct).
