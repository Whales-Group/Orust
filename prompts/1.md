# Project: ORust (.or): an OOP-friendly front end for Rust

## What we're building
ORust is a transpiler plus tooling that lets developers coming from OOP languages (Dart, Java, C#, Swift) write Rust through familiar vocabulary. It is NOT a new runtime or a reimplementation of Rust semantics. ORust source (`.or`) compiles to plain Rust, `rustc` does the real type and borrow checking, and our main value-add is translating rustc errors back into friendly, OOP-flavored messages that point at `.or` source lines.

Core principle: `class` is a friendlier spelling of `struct` + `impl`. It looks like a class but behaves like Rust. Ownership stays real. We rename it; we never hide it by default.

## Tech choices
- Implementation language: Rust, Cargo workspace.
- Lexer: `logos`. Parser: `chumsky` (or hand-written recursive descent if error recovery is easier). Keep spans on every AST node.
- Codegen: emit Rust as text via a small pretty-printer (or `quote`/`prettyplease`). Output goes to a generated cargo project under `target/orust/`.
- Diagnostics: run `cargo check --message-format=json`, parse the output, map spans back to `.or` using a span table recorded during codegen.
- CLI: `orust check <file.or>`, `orust build <file.or>`, `orust run <file.or>`, `orust emit <file.or>` (prints the generated Rust).
- Crates: `orust-syntax` (lexer, parser, AST), `orust-lower` (inference of mut/lifetimes, desugaring), `orust-emit` (Rust codegen + span table), `orust-diag` (rustc error translator), `orust-cli`.

## Language surface (v0.1 scope)
| ORust | Emitted Rust |
|---|---|
| `class Foo { int x = 0; void inc() { x++; } }` | `struct Foo { x: i32 }` + `impl Foo { fn new() -> Self; fn inc(&mut self) }` |
| `new Foo()` | `Foo::new()` |
| `this` | `self` |
| `interface Speak { String speak(); }` | `trait Speak { fn speak(&self) -> String; }` |
| `class Dog implements Speak` | `impl Speak for Dog` |
| `var x = ...;` | `let x = ...;` (add `mut` automatically if mutated) |
| `lend T` / `lend a` | `&T` / `&a` |
| `lend mut T` / `lend mut a` | `&mut T` / `&mut a` |
| `copy a` | `a.clone()` |
| `T?` | `Option<T>` |
| `int`, `double`, `bool`, `String` | `i32`, `f64`, `bool`, `String` |
| `[1, 2, 3]`, `List<T>` | `vec![..]`, `Vec<T>` |
| `print(x)` | `println!("{}", x)` |
| `shared class Foo` | `Rc<RefCell<FooData>>` with auto `.borrow()` / `.borrow_mut()` / `.clone()` (milestone 5) |
| `rust { ... }` | raw Rust passthrough block (milestone 6) |

Deliberate omissions: NO inheritance (`extends`), NO hidden `Rc<RefCell>` unless the class is marked `shared`, NO garbage collection.

Inference rules:
- `mut` is inferred from usage (assignment, `lend mut`, calling a method that needs `&mut self`).
- Method receivers: infer `&self` vs `&mut self` vs `self` from the method body.
- Function parameters: plain `T` means move, `lend T` means `&T`, `lend mut T` means `&mut T`.
- Lifetimes: rely on Rust elision. If a function returns a `lend` and there are multiple `lend` inputs, emit a single shared lifetime `'a` on all of them. If that is ambiguous, error and ask for `lend(a) T f(...)` syntax.

## Example program (must work by the end of milestone 2)
```
class Counter {
  int count = 0;
  void inc() { count++; }
  int get() { return count; }
}

void show(lend Counter c) {
  print(c.get());
}

void main() {
  var a = new Counter();
  a.inc();
  show(lend a);
  show(lend a);
}
```
Expected emitted Rust (shape, not exact formatting):
```rust
struct Counter { count: i32 }
impl Counter {
    fn new() -> Self { Counter { count: 0 } }
    fn inc(&mut self) { self.count += 1; }
    fn get(&self) -> i32 { self.count }
}
fn show(c: &Counter) { println!("{}", c.get()); }
fn main() {
    let mut a = Counter::new();
    a.inc();
    show(&a);
    show(&a);
}
```

## Error translator (the real product)
Parse rustc JSON diagnostics, map spans back to `.or`, and rewrite by error code into plain OOP-flavored language. Always show the `.or` source lines (never the generated Rust), explain what happened in one sentence, and offer concrete fixes using ORust vocabulary (`copy`, `lend`, `lend mut`, `shared class`). Fall back to a cleaned-up version of the original rustc message when there is no template.

Templates needed:
- E0382 use after move: "`a` no longer has its Counter" with fixes: `copy a`, `lend a`, make the class `shared`.
- E0499 two mutable borrows: "two things are trying to edit `a` at once. Only one editor at a time."
- E0502 mutable borrow while borrowed: "you changed `items` while `first` was still looking at it."
- E0106 missing lifetime: should be rare because we infer; if it fires, ask for `lend(a)` syntax.
- E0505 move out while borrowed.

Example target output:
```
error: `a` no longer has its Counter
 --> main.or:3:9
  |
2 |   var b = a;      // a handed its Counter to b here
3 |   print(a.get()); // but a is used again here
  |
help: give b its own Counter:    var b = copy a;
help: let b look without owning: var b = lend a;
help: have both see the same one: make Counter a `shared class`
```

## Milestones (do them in order; commit after each; keep tests green)
1. **Skeleton + hello world:** workspace, lexer, parser for `class`, fields, methods, `var`, `print`, `if`/`while`/`for`, literals, basic expressions. `orust emit` and `orust run` work for a single-class program.
2. **Borrowing:** `lend`, `lend mut`, `copy`, `new`, `this`, inferred `mut` and `&self`/`&mut self`. The example program above runs.
3. **Span table + diagnostics plumbing:** record `.or` to `.rs` span mappings in codegen. Run `cargo check` JSON, map errors back to `.or` locations.
4. **Error translator:** E0382, E0499, E0502 templates with golden tests (input `.or`, expected friendly output).
5. **Interfaces and Option:** `interface`, `implements`, `T?`, `?.`, `??`, `if`-null-checks.
6. **`shared class`:** Rc/RefCell emission with auto borrow insertion, plus runtime panic message rewriting.
7. **Lifetime inference + `rust { }` passthrough.**

## Testing requirements
- Golden tests: `tests/cases/*.or` with `*.rs` (expected emitted Rust) and `*.err` (expected friendly error, when applicable). Use `insta` or a simple snapshot harness.
- Every example in this prompt becomes a test case.
- End-to-end test: compile and run the sample programs and assert on stdout.
- Parser tests for syntax errors with helpful messages and spans.

## Working rules
- Start with milestone 1 now. Don't stop to ask questions; when something is ambiguous, pick the simplest option that fits the core principle, and record the decision in `docs/decisions.md`.
- Keep the AST and span plumbing clean from day one; the error translator depends on it.
- Never reimplement the borrow checker. rustc is the source of truth.
- Prefer small, reviewable commits. Write a README with the language tour (use the tables above) and a `docs/error-translation.md` explaining the template approach.
- Name the CLI binary `orust` and the file extension `.or`.

Begin by creating the workspace, the lexer/parser for milestone 1, and the first golden test. Then continue through the milestones.
