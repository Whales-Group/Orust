# ORust Phase 2: Dart-style async + polymorphism

Read AGENTS.md first. All hard rules there still apply (never reimplement the borrow checker, no inheritance, no hidden Rc/RefCell, errors shown in .or terms). This phase adds three things: Dart-style Futures on tokio, polymorphism (dynamic dispatch, generics, enums), and a few quality-of-life features. Continue the milestone numbering from AGENTS.md (start at 8).

## Goal
Someone who knows Dart's `Future`, `async`/`await`, and `try/catch` can write concurrent ORust without ever typing `#[tokio::main]`, `Pin<Box<dyn Future>>`, `Send + 'static`, `JoinHandle`, or `Box<dyn Trait>`. Rust semantics stay real underneath. We rename and automate boilerplate; we do not fake Dart's runtime.

## Part A: Futures on tokio

### Surface syntax and emission
| ORust | Emitted Rust |
|---|---|
| `Future<int> fetch() async { ... }` | `async fn fetch() -> i32 { ... }` |
| `var x = await fetch();` | `let x = fetch().await;` |
| `void main() async { ... }` | `#[tokio::main] async fn main() { ... }` (auto, user never writes it) |
| `await Future.delayed(1.seconds)` | `tokio::time::sleep(Duration::from_secs(1)).await` |
| `await Future.wait([a(), b(), c()])` | `tokio::join!` for fixed arity, `futures::future::join_all` for lists |
| `Future.any([a(), b()])` | `tokio::select!` / `futures::future::select_all` |
| `var t = spawn work();` | `tokio::spawn(work())`, type `Task<T>` (wraps `JoinHandle<T>`) |
| `await t;` | `t.await` with join errors surfaced as ORust `Error` |
| `Future<T>.then(f)`, `.catchError(f)`, `.timeout(d)` | thin helpers in the runtime crate |
| `Stream<T>`, `await for (var x in s)` | `futures::Stream` + `while let Some(x) = s.next().await` |
| `Channel<T>` with `.send()` / `.receive()` | `tokio::sync::mpsc` (milestone 12, optional) |

### Critical semantic decision (document in docs/async.md)
Dart futures start eagerly. Rust futures are lazy. ORust keeps Rust's behavior and makes it visible:
- Calling an `async` function gives a lazy `Future<T>`. It does nothing until `await`ed, passed to `Future.wait`, or `spawn`ed.
- `spawn f()` is the explicit "start it now, in the background" and returns a `Task<T>`.
- If a `Future` is created and dropped without being awaited or spawned, emit a friendly warning: "`fetch()` makes a Future but nothing ever awaits it, so it never runs. Add `await`, or use `spawn` to run it in the background."

### Errors in async code
- Add a runtime crate `orust-runtime` (re-exports tokio and futures, defines `Error`, `Task<T>`, `Duration` helpers like `1.seconds`, `250.millis`). The generated cargo project depends on it.
- `Error` is a boxed `dyn std::error::Error + Send + Sync` wrapper with a message and optional cause. `throw Error("msg")` emits `return Err(Error::new("msg"))`.
- A function marked `throws` returns `Result<T, Error>`. Inside any `throws` function, `await` on a throwing future gets `?` inserted automatically. `try { ... } catch (e) { ... }` emits a `match`.
- `Future<int> f() async throws` becomes `async fn f() -> Result<i32, Error>`.

### Borrowing across async (the hard part)
- `lend` parameters on async functions are fine as long as the future is awaited in the same scope. Emit normal references and let rustc check it.
- `spawn` requires everything used inside to be owned (`'static + Send`). Do NOT hide this. Rewrite the rustc errors (E0373 closure may outlive, E0277 `Send` not satisfied, E0597/E0521 borrowed value does not live long enough) into plain advice:
  - "`spawn` runs in the background, so it can't borrow things from this function. Give it its own copy with `copy a`, move it in, or make the class `shared`."
- `shared class` emission becomes context-sensitive: if the program contains any `spawn`, shared classes emit `Arc<tokio::sync::Mutex<FooData>>` with `.lock().await` inserted automatically (only legal inside `async` functions; otherwise give a friendly error). If there is no `spawn`, keep `Rc<RefCell<>>`. Record this decision in docs/decisions.md.

### Example that must work (milestone 8 acceptance)
```
class Api {
  Future<String> getUser(int id) async {
    await Future.delayed(100.millis);
    return "user-$id";
  }
}

void main() async {
  var api = new Api();
  var results = await Future.wait([api.getUser(1), api.getUser(2), api.getUser(3)]);
  for (var r in results) { print(r); }

  var t = spawn heavy();
  print("doing other work");
  print(await t);
}

Future<int> heavy() async {
  await Future.delayed(50.millis);
  return 42;
}
```
Expected emitted Rust shape:
```rust
use orust_runtime::*;
struct Api;
impl Api {
    fn new() -> Self { Api }
    async fn get_user(&self, id: i32) -> String {
        sleep(millis(100)).await;
        format!("user-{}", id)
    }
}
#[tokio::main]
async fn main() {
    let api = Api::new();
    let results = futures::future::join_all(vec![api.get_user(1), api.get_user(2), api.get_user(3)]).await;
    for r in results { println!("{}", r); }
    let t = Task::spawn(heavy());
    println!("doing other work");
    println!("{}", t.await);
}
async fn heavy() -> i32 { sleep(millis(50)).await; 42 }
```

## Part B: Polymorphism

### Interfaces as types (dynamic dispatch, hidden boilerplate)
- A variable, field, list element, or return type whose declared type is an `interface` means "any class that implements it". Emit `Box<dyn Trait>` for owned values, `&dyn Trait` for `lend Speak`, `&mut dyn Trait` for `lend mut Speak`. `List<Speak>` becomes `Vec<Box<dyn Speak>>`. Auto-insert `Box::new(...)` when a concrete class is assigned to an interface-typed slot.
- For async interfaces (methods that return `Future`), emit `#[async_trait::async_trait]` automatically.
- Add `Send + Sync` supertraits automatically when the program uses `spawn`.
- Interface default methods: `interface Shape { double area(); String describe() { return "area=${area()}"; } }` emits trait default methods.
- Rewrite E0038 (trait is not dyn-compatible) into: "`Foo` can't be used as a plain type because method `bar` returns/takes `Self` or has its own generics. Make it generic (`T extends Foo`) instead."

### Generics (static dispatch)
- `class Box<T>`, `T first<T>(List<T> xs)`, constraints with `T extends Comparable & Printable` emitting trait bounds and `where` clauses.
- Infer simple bounds from usage where possible (calling `.compareTo` implies a `Comparable` bound).
- Rewrite E0277 (trait bound not satisfied) and E0599 (method not found for generic T) into "you called `x.foo()` but T could be anything; write `T extends Foo`".

### Enums with data and pattern matching (closed polymorphism)
```
enum Shape {
  Circle(double radius),
  Rect(double w, double h),
}

double area(lend Shape s) {
  return switch (s) {
    Circle(r) => 3.14159 * r * r,
    Rect(w, h) => w * h,
  };
}
```
Emit Rust `enum` + `match`. Missing cases must surface rustc's E0004 as "you didn't handle every kind of Shape: missing `Rect`". Support `if (x case Circle(r))` as `if let`.

### Other features in this phase
- **Operator overloading:** `operator +(Vec2 o)` emits `impl Add for Vec2`. Support `+ - * / == < > []`.
- **Extensions:** `extension on String { bool get isShout => ... }` emits an extension trait.
- **Auto-derive:** `@data class` derives `Debug, Clone, PartialEq, Eq, Hash` where fields allow it. Plain `class` derives `Debug` only. `toString()` maps to `Display`.
- **Closures:** `(x) => x * 2` and `(x) { ... }` emit Rust closures; infer `move` for closures passed to `spawn`. Function types like `int Function(int)` emit `impl Fn(i32) -> i32` in parameter position and `Box<dyn Fn(i32) -> i32>` when stored.
- **Named and optional parameters:** `void f(int a, {int b = 1, required int c})` emits a generated params struct (with `Default` where defaults exist). Call sites `f(1, c: 3)` are rewritten accordingly.
- **Collection helpers:** `.map`, `.where`, `.fold`, `.forEach`, `.any`, `.every`, `.first`, `.last`, `.isEmpty` on `List`/`Map`/`Set`, emitted as iterator chains with `.collect()`.
