# ORust Phase 4 + 5 + Tooling: Drop, borrowed fields, errors, numbers, testing, stdlib, then deeper Rust

Read AGENTS.md first. All hard rules still apply: rustc is the source of truth (never reimplement the borrow checker or privacy checks), no inheritance, no hidden Rc/RefCell, errors are always shown in .or terms, nothing is hidden by default. Continue milestone numbering from the last completed one (Phase 3 ended at 22). Work in order. Do not start Phase 5 until Phase 4 tests are green.

## Goals
- Phase 4 makes the language "feel complete" for everyday programs: cleanup, classes that borrow, real error types, correct integer types, built-in tests, and a stdlib so nobody touches raw `std::fs`.
- Phase 5 adds the Rust depth OOP developers need next: recursive types, slices, richer pattern matching, iterators, traits, records and newtypes.
- The Tooling Track (T1-T6) is independent of the compiler core and can be interleaved, but formatter and LSP work should start only after Phase 5's grammar is stable.

## Cross-cutting rules for this whole prompt
1. **Stable error codes.** Every friendly diagnostic gets an ORust code `OR0001`, `OR0002`, ... registered in `docs/error-codes.md` with: the rustc code(s) it translates, the friendly template, and a long-form explanation. Codes never change once released.
2. **Runtime panics are translated too.** The `orust-runtime` crate installs a panic hook (debug and release) that maps the Rust panic location back to `.or` using the span table and prints friendly text. Required translations: arithmetic overflow, divide by zero, index out of bounds ("index 5 is out of range for a List of length 3"), `RefCell` already borrowed (shared classes), `unwrap` on None, explicit `throw` escaping `main`. The raw Rust panic message is shown only with `ORUST_BACKTRACE=1`.
3. **Feature-gated generated Cargo.toml.** The generated project depends only on what the program imports. Importing `std:http` adds reqwest; a program that does not import it must not compile it.
4. **Never fake semantics.** If something cannot be done cleanly without hiding ownership, emit a clear "not supported yet" error (with an OR code) and move on.
5. **Decisions log.** Every ambiguous choice goes in `docs/decisions.md` with a one-line rationale.
6. **Regenerate affected goldens deliberately.** When a change alters emitted Rust for old tests (for example `int` becoming `i64`), review the snapshot diffs and commit them separately, with the message `goldens: <reason>`.

# PHASE 4

## Milestone 23: Foundations
1. **`int` is 64-bit.** `int` emits `i64` (Dart's int is 64-bit); `double` stays `f64`. Update every earlier mapping table and golden test. Collection `.length` returns `int` (emit `.len() as i64`). Indexing with an `int` emits a checked conversion to `usize` (a negative index panics with the friendly message from rule 2 above).
2. **Literal widening.** `double x = 5;` is allowed (integer literal widens to double). Mixing an `int` variable and a `double` in arithmetic is an error: "can't add an `int` and a `double`; use `n.toDouble()`" (translate E0277 and E0308).
3. **`print` of a nullable** prints the value or `null` (runtime helper trait; users never see Rust's `Option` debug format).
4. **Constructors.** If not already implemented, add Dart-style constructors: `Foo(this.a, this.b);` (initializing formals), constructor bodies, named constructors `Foo.empty()`, and `factory`. Emit `pub fn new(...)` / `pub fn empty()`.
5. **Panic hook + OR-code registry** (rules 1 and 2 above), plus `main() throws`: `void main() throws { ... }` emits `fn main() -> Result<(), Error>`; the runtime prints errors in friendly form and exits with code 1.

## Milestone 24: Destructors (`Drop`)
OOP developers know this as RAII / `dispose` / `close`. It also teaches ownership: when the owner goes away, cleanup runs.

| ORust | Emitted Rust |
|---|---|
| `class File { on drop { close(); } }` | `impl Drop for File { fn drop(&mut self) { self.close(); } }` |
| `drop a;` | `drop(a);` (explicit early release; `a` is moved) |
| `scope`-end of an owner | automatic (Rust semantics, unchanged) |

Rules:
- At most one `on drop` per class. Its body is an implicit `lend mut this` context.
- `on drop` cannot be `async` and cannot `await`. Friendly error: "`on drop` can't wait for async work. Add a `close()` method callers `await` before the object goes away" (translate E0728 inside drop).
- Drop order follows Rust: locals in reverse declaration order, fields in declaration order. Document in docs/drop.md with a runnable example.
- A `shared class` runs `on drop` when the last owner goes away. Add a test that shows exactly when.
- Throwing from `on drop` is not allowed (it has no return value); a runtime panic inside drop is left to Rust's behavior.
- Copy types cannot have `on drop`. `@data` classes that have `on drop` do not derive `Copy`.

Acceptance program:
```
class Guard {
  String name;
  Guard(this.name);
  on drop { print("release $name"); }
}

void main() {
  var a = new Guard("a");
  {
    var b = new Guard("b");
    print("inner");
  }
  var c = a;       // moved, not dropped
  drop c;          // explicit early release
  print("end");
}
```
Expected stdout, in order: `inner`, `release b`, `release a`, `end`.

Diagnostics to translate:
| rustc | Friendly |
|---|---|
| E0040 explicit destructor call | "you can't call `on drop` yourself. Use `drop a;` to release it early." |
| E0509 move out of type that implements Drop | "can't take `name` out of a `Guard` because Guard cleans up after itself. Use `copy g.name` or give Guard a method that returns it." |
| E0184 Copy + Drop | "a class with `on drop` can't be copied bit-for-bit; use `copy` (clone) instead." |
| E0382 use after `drop a;` | normal use-after-move message, with note "`drop a;` released it here." |

## Milestone 25: Classes that hold `lend` fields
Classes may declare `lend T field` and `lend mut T field`. The compiler infers and emits the lifetime parameters; users never write `'a`.

Rules:
- Default: one shared lifetime `'a` for all `lend` fields of a class. Emit `struct Reader<'a>`, `impl<'a> Reader<'a>`, constructor `new(text: &'a String)`. Log this decision; allow `lend(x)` grouping in a later phase.
- References to the class in signatures get an elided lifetime written `Reader<'_>` (so the `elided_lifetimes_in_paths` lint is not triggered). Emit explicit lifetimes only when elision fails, then reuse the E0106 `lend(a)` ask from earlier phases.
- A class with `lend` fields cannot be `shared`, cannot be `spawn`ed with borrowed data, and cannot be stored in an interface-typed slot unless the trait object gets `+ 'a`. Emit `Box<dyn Trait + 'a>` automatically where needed.
- A class with `lend` fields and `on drop` triggers rustc's drop-check errors; translate them (see below).

Acceptance program:
```
class Reader {
  lend String text;
  int pos = 0;
  Reader(this.text);
  bool done() { return pos >= text.length; }
  void advance() { pos++; }
}

void main() {
  var s = "hello";
  var r = new Reader(lend s);
  while (!r.done()) { r.advance(); }
  print(r.pos);        // 5
}
```
Expected emitted shape:
```rust
struct Reader<'a> { text: &'a String, pos: i64 }
impl<'a> Reader<'a> {
    fn new(text: &'a String) -> Self { Reader { text, pos: 0 } }
    fn done(&self) -> bool { self.pos >= self.text.len() as i64 }
    fn advance(&mut self) { self.pos += 1; }
}
```
Negative tests (each must produce a friendly error with the `.or` lines):
```
Reader make() { var s = "x"; return new Reader(lend s); }       // E0515 / E0597
void f() { var r; { var s = "x"; r = new Reader(lend s); } print(r.pos); }   // E0597
void g() { var s = "x"; var r = new Reader(lend s); s = "y"; print(r.pos); } // E0506
```
| rustc | Friendly |
|---|---|
| E0515 return reference to local | "`make` returns a Reader that is still looking at `s`, but `s` ends when `make` ends. Return an owned value (`copy s` into a class that owns its text) or pass `s` in from outside." |
| E0597 does not live long enough | "`r` outlives `s`. `r` is looking at `s`, so `s` has to stay alive as long as `r` does. Declare `s` earlier or finish with `r` sooner." |
| E0506 assign to borrowed value | "you changed `s` while `r` was still looking at it." |
| E0597 via `on drop` (drop-check) | "`r` runs cleanup code (`on drop`) that may still look at `s`, so `s` must outlive `r`. Declare `s` before `r`." |

## Milestone 26: Integer types, overflow, conversions
- Types: `int` (i64), `i8 i16 i32 i128 isize`, `u8 u16 u32 u64 u128 usize`, `double` (f64), `f32`. Suffix-free literals take their type from context; `250u8` suffix form is also allowed. Hex, binary, octal, and `_` separators work.
- **Overflow semantics: checked in every profile** (emit `overflow-checks = true` under `[profile.release]` in the generated Cargo.toml; configurable via `[profile] overflow_checks = false` in orust.toml). Decision rationale for docs/decisions.md: OOP developers do not expect silent wrap-around.
- Helper methods on all integer types (emitted as the matching Rust methods):
  `checkedAdd/Sub/Mul/Div/Pow` returning `T?`, `wrappingAdd/Sub/Mul`, `saturatingAdd/Sub/Mul`, `abs`, `pow`, `min`, `max`, `clamp`, `isEven`, `isOdd`, `signum`.
- Conversions: `x as u8` is a plain numeric cast (Rust semantics: truncating) and triggers a warning when it narrows ("may lose data; use `x.toChecked<u8>()` which returns `u8?`"). `x.toChecked<T>()` emits `T::try_from(x).ok()`. `x.toDouble()`, `d.toInt()` (truncates), `d.round()`, `d.floor()`, `d.ceil()` return `int`.
- Mixing integer types is an error with a fix: "can't add `u8` and `int`; convert one: `a.toChecked<int>()` or `b as u8`" (translate E0277, E0308).
- Compile-time lints that rustc denies by default must be translated: `arithmetic_overflow` ("this calculation always overflows") and `overflowing_literals` ("300 doesn't fit in a `u8` (0 to 255)").

Acceptance program:
```
void main() {
  u8 small = 250;
  print(small.checkedAdd(10));      // null
  print(small.wrappingAdd(10));     // 4
  print(small.saturatingAdd(10));   // 255
  int big = 9223372036854775807;
  print(big.checkedAdd(1));         // null
  var n = 300;
  print(n.toChecked<u8>());         // null
  double d = 5;                     // literal widening
  print(d);                         // 5.0
}
```
Runtime test: `u8 x = 255; x = x + 1;` panics with the friendly overflow message pointing at the `.or` line ("`u8` can't go above 255").

## Milestone 27: Error types
Typed errors that work with `throws`, `try/catch`, and `?`. Model: Rust's `thiserror`, but generated by hand (no extra dependency) so messages can interpolate fields.

Syntax:
```
error NotFound { String path }                    // single-case error (struct)

error ConfigError {                               // multi-case error (enum)
  Missing(String key)            => "missing key: $key",
  Invalid(String key, String why) => "bad value for $key: $why",
  Io(IoError cause) from         => "could not read config: $cause",
}
```
Emission:
- Single-case: `struct NotFound { path: String }` with `Display` (message defaults to the class name plus fields unless `=> "..."` is given), `Debug`, and `std::error::Error`.
- Multi-case: `enum ConfigError { Missing { key: String }, ... }` with `Display`, `Debug`, `Error`.
- `from` on a case generates `impl From<IoError> for ConfigError` and sets `source()` to the cause. This is what makes `?` convert automatically.
- `throws ConfigError` (typed) emits `Result<T, ConfigError>`. Bare `throws` keeps meaning `Result<T, orust_runtime::Error>`; any error type converts into `Error` via a `From<E: std::error::Error + Send + Sync + 'static>` impl. `orust_runtime::Error` must NOT itself implement `std::error::Error` (same coherence trick as `anyhow`); document why in docs/decisions.md.
- `throw ConfigError.Missing("name")` emits `return Err(ConfigError::Missing { key: ... }.into())` with the right conversion.
- Catching: `catch (e)` catches everything; `on ConfigError catch (e)` matches that type (downcast when the function's error type is the erased `Error`). `e.message`, `e.source` (the cause, as `Error?`), and `toString()` are always available. `rethrow;` re-raises. Pattern-match the cases with `switch (e) { Missing(key) => ..., _ => ... }`.
- Stretch: `finally { ... }` implemented with a runtime scope guard; if it cannot be made correct across `await` and early `return`, emit "not supported yet" instead of guessing.
- Errors are `Send + Sync + 'static` by construction, so they work with `spawn` from Phase 2.

Acceptance program:
```
error ConfigError {
  Missing(String key)    => "missing key: $key",
  Io(IoError cause) from => "could not read config: $cause",
}

String load(String path) throws ConfigError {
  var text = File.readString(path);      // throws IoError, converted by `from`
  if (text.isEmpty) { throw ConfigError.Missing("name"); }
  return text;
}

void main() {
  try {
    print(load("does-not-exist.cfg"));
  } on ConfigError catch (e) {
    print(switch (e) {
      Missing(key) => "add $key",
      _ => "failed: $e",
    });
  }
}
```
Expected stdout: `failed: could not read config: ...` (the IoError text names the missing file).

Diagnostics:
| rustc | Friendly |
|---|---|
| E0277 `?` couldn't convert the error | "`load` says it throws `ConfigError`, but this line can throw `JsonError`. Add `Json(JsonError cause) from` to ConfigError, or change `throws` to plain `throws` to accept any error." |
| E0277 `?` in function that returns nothing | "this line can fail, but `main` doesn't say `throws`. Add `throws` or wrap it in `try/catch`." |
| E0599 method not found on error | suggest `e.message` / `e.source`. |

## Milestone 28: Built-in testing and doc comments
Syntax:
```
int add(int a, int b) { return a + b; }

test "adds numbers" { expect(add(1, 2) == 3); }
test "shows both sides" { expect(add(1, 1) == 3); }
test async "waits" { await Future.delayed(10.millis); expect(true); }
test "throws" { expectThrows<ConfigError>(() => load("nope.cfg")); }
group "math" { test "negatives" { expect(add(-1, 1) == 0); } }
```
Emission and behavior:
- Each file's tests go in a `#[cfg(test)] mod tests { use super::*; ... }` so tests can use file-private items. `test` becomes `#[test]`, `test async` becomes `#[tokio::test]`, `group` becomes a nested module. Test names are sanitized for Rust identifiers and a name map restores the original string in output.
- `expect(a == b)` emits `assert_eq!` (so failures print both sides); every other `expect(cond)` emits `assert!` with the source expression text. Also provide `expectNot`, `expectNull`, `expectNotNull`, `expectApprox(a, b, tolerance)`, `expectThrows<T>(fn)`, `fail("message")`.
- `orust test [filter]` runs `cargo test`, parses the output, and prints results in ORust format with `.or` file:line for each failure:
```
PASS adds numbers
FAIL shows both sides  (math.or:5)
  expect(add(1, 1) == 3)
    left:  2
    right: 3
2 passed, 1 failed
```
- Exit code is nonzero on failure. `--list` lists test names. `--nocapture` shows `print` output.
- Doc comments: `///` before a declaration and `//!` at the top of a file pass through to Rust doc comments. `orust doc` runs `cargo doc` on the generated tree. Fenced examples in doc comments are not compiled (stretch: run them as doc tests, mapping errors back to `.or`).

## Milestone 30: `orust-std` data (json, regex, http)
- **`std:json`**: annotate a class with `@json` (derives Serialize and Deserialize). Field names are camelCase in JSON by default (the naming bridge from Phase 3 converts to snake_case Rust fields; emit `#[serde(rename_all = "camelCase")]`); `@json(name: "user_id")` on a field overrides. `T?` fields are nullable and tolerate a missing key. Nested classes and `List<T>`/`Map<String, T>` fields require their element types to be `@json` too.
  API: `json.encode(x)`, `json.encodePretty(x)`, `json.decode<T>(text) throws JsonError`, and a dynamic `JsonValue` (`json.parse(text)`, indexing `v["a"][0]`, `.asString`, `.asInt`, `.asList`, `.isNull`, each returning nullable results).
- **`std:regex`**: `Regex(pattern) throws`, `hasMatch(s)`, `firstMatch(s)` returning `Match?`, `allMatches(s)`, `match.group(1)`, `replaceAll(s, replacement)`, `split(s)`.
- **`std:http`** (async only, reqwest with rustls, feature-gated): `await http.get(url)`, `await http.post(url, body: ..., headers: {...})`, `new HttpClient(timeout: 10.seconds)`; `response.status`, `await response.text()`, `await response.json<T>()`, `response.headers`. Acceptance program:
```
import 'std:json' show json;

@json class Address { String city; }
@json class User {
  String name;
  int? age;
  List<String> tags;
  Address address;
}

void main() throws {
  var u = json.decode<User>('{"name":"ada","age":36,"tags":["math"],"address":{"city":"London"}}');

  print(json.encode(u));
}
```

# PHASE 5

## Milestone 32: Recursive types (auto-boxing)
Users write `class Node { int value; Node? next; }` and it just works. Rust needs `Box` for infinite-size types (E0072); the compiler inserts it.
- Build a containment graph of all class and enum fields. Edges are direct embeddings: plain field types, `T?` (Option), tuples, records. Not edges: `List`, `Map`, `Set`, `shared`, existing `Box`/`Rc`/`Arc`.
- Find strongly connected components. In each, box exactly one edge to break each cycle, chosen deterministically (prefer an `Option` field; otherwise the last declared). Record the rule in docs/decisions.md.
- Insert `Box::new(...)` at construction sites and the matching deref at reads and pattern matches. Users never see `Box`.
- Emit an informational note (not a warning) in `orust check --verbose`: "`Node.next` is stored on the heap, one allocation per Node."
- E0072 must never reach the user. If rustc reports it, treat it as a compiler bug and print "internal error OR9000: please report" with the `.or` file.
- Required tests: singly linked list with push/pop and iteration, binary search tree (insert and in-order traversal), an expression-tree enum evaluator (`enum Expr { Num(int n), Add(Expr l, Expr r), Mul(Expr l, Expr r) }` with a `switch` evaluator), and mutual recursion (`Tree` has `Forest`, `Forest` has `List<Tree>`, which needs no box, and a second case that does).

## Milestone 33: Slices and string types
- Parameter and return positions: `lend String` becomes `&str`; `lend List<T>` becomes `&[T]`; `lend mut List<T>` becomes `&mut [T]` when the body only reads, writes by index, sorts, or swaps, and `&mut Vec<T>` when it adds or removes. The compiler infers which from the body. Fields: `lend String` in classes becomes `&'a str`. Call sites work unchanged because of deref coercion.
- Slice expressions: `s[1..4]`, `xs[..3]`, `xs[2..]`, `xs[1..=3]` produce borrowed views (they are implicitly `lend`). Binding one to a variable makes it a borrow subject to normal rules, so the Phase 1 "changed while looking" errors apply.
- `String.length` is the byte length (O(1), same as Rust). Provide `charCount` (O(n)), `substring(startChar, endChar)` (char-based), `chars`, `bytes`, `lines`, `split`, `trim`, `contains`, `startsWith`, `endsWith`, `replaceAll`, `toUpperCase`, `toLowerCase`, `indexOf`. Document the byte-versus-char distinction in docs/strings.md and add a lint when `.length` is used on a string that is indexed with `[]`.
- Slicing a string on a non-character boundary panics at runtime; translate it: "byte 3 is in the middle of a character".
- Diagnostics: E0308 (`&String` vs `&str` mismatches that coercion cannot fix), E0277 "size cannot be known at compile time" for `str`/`[T]` used by value (friendly: "you can't hold a slice by itself; use `lend` or copy it into a `List`/`String` with `copy`").

## Milestone 34: Richer pattern matching
Extend `switch`, `if case`, and `var` declarations:
- **Destructuring declarations:** `var (a, b) = pair;`, `var Point(x, y) = p;`, nested patterns, `_` wildcards, `..` rest in lists (`[first, ..rest]` slice patterns).
- **Guards:** `Circle(r) when r > 0 => ...` emits `Shape::Circle(r) if r > 0 => ...`.
- **Or-patterns and ranges:** `Circle(_) | Square(_) => ...`, `1..=5 => ...`, `n @ 1..=5 => ...`.
- **Nullable patterns:** `switch (opt) { null => "none", var v => "has $v" }`.
- **Refutable binding with else:** `var Circle(r) = shape else { return; };` emits `let Shape::Circle(r) = shape else { return };`.
- **`while case`:** `while (it.next() case var x?) { ... }` emits `while let Some(x) = ...`.
- Binding mode: patterns on a `lend` value bind by reference automatically; matching an owned value moves out the bindings, and the usual E0382 message applies afterward.
- Diagnostics: E0004 non-exhaustive ("you didn't handle every kind of Shape: missing `Rect`, and the `Circle` case only handles `r > 0`"), E0005 refutable pattern in a plain `var` ("this pattern may not match; add `else { ... }`"), unreachable-pattern warning.

## Milestone 35: Iterators and iterable classes
- A class can `implements Iterator<T>` by providing `T? next()`, which emits `impl Iterator for X { type Item = T; fn next(&mut self) -> Option<T> }`. All adaptor methods then work for free.
- A class can `implements Iterable<T>` by providing `Iterator<T> iterator()`, which emits `IntoIterator for &X` and enables `for (var x in collection)`.
- **Lazy by default, like Dart's `Iterable`:** `.map`, `.where`, `.take`, `.skip`, `.zip`, `.enumerate`, `.expand`, `.takeWhile`, `.skipWhile`, `.chain` are lazy. Terminal operations: `.toList()`, `.toSet()`, `.toMap()`, `.fold`, `.reduce`, `.sum`, `.count`, `.first`, `.last`, `.any`, `.every`, `.min`, `.max`, `.join(sep)`, `.forEach`. This replaces the eager `.collect()` behavior from Phase 2 (update those goldens).
- Type `Iterator<T>` in a return position emits `impl Iterator<Item = T>`; stored in a field or returned from branches it emits `Box<dyn Iterator<Item = T> + '_>`.
- `for (var x in list)` borrows (iterates by reference). To consume the list and take ownership of elements, write `for (var x in list.consume())`. Log this decision.
- Friendly error when a lazy chain still borrows a list that is then modified (E0502/E0499): "this chain is still reading `items`; call `.toList()` first, or finish iterating before calling `add()`."
- Required tests: a `Countdown` iterator class, a `Library implements Iterable<Book>`, a chain mixing `where`/`map`/`toList`, and the borrow error above.

## Milestone 36: Traits beyond interfaces
Expose Rust's standard traits under OOP-friendly names while still allowing graduation to real trait vocabulary.
- **Interface extension** (interfaces only, never classes): `interface Pet extends Animal` emits supertraits.
- **Associated types:** `interface Container { type Item; Item get(int i); }` emits `type Item;`. Implementers write `type Item = String;`.
- **Standard traits via `implements`:**
| ORust | Rust |
|---|---|
| `implements Comparable<T>` with `int compareTo(T o)` | `Ord` + `PartialOrd` (requires `==`, from `@data` or `operator ==`) |
| `implements From<U>` with `static T from(U u)` | `impl From<U> for T` (and `.into()` works) |
| `implements Default` with `static T create()` or `@data` field defaults | `impl Default for T` |
| `implements Hashable` or `@data` | `Hash` + `Eq` |
| `toString()` | `Display` (unchanged from Phase 2) |
- **Auto-derive by usage:** `copy a` on a class with no `Clone` makes the compiler derive `Clone` if every field is clonable; otherwise error "Counter can't be copied because field `socket` can't be. Remove `copy` or make `socket` a `shared` value."
- **Static dispatch vs dynamic dispatch is visible:** `T extends Comparable` is generic (static); `Comparable` as a plain type is `dyn` (and E0038 translations from Phase 2 apply).
- Diagnostics: E0046 (missing methods: "`Dog` says it implements `Speak` but doesn't define `speak()`"), E0053/E0050 (wrong signature, show expected vs actual in ORust syntax), E0407 (method not in interface), E0119 (two implementations conflict), E0191/E0220 (associated type missing/unknown).

## Milestone 37: Records, tuples, type aliases, newtypes
- **Tuples:** `(int, String) pair = (1, "a");` emits a Rust tuple. Positional access `pair.$1`, `pair.$2`.
- **Named records:** `({int x, int y}) p = (x: 1, y: 2);` Rust has no anonymous structs, so emit a generated struct per distinct shape in a generated `orust_records` module, canonically named from field names and types (deduplicated across files, `pub`, deriving `Debug, Clone, PartialEq, Eq, Hash, Copy` where fields allow).
- **Aliases:** `typedef UserId = int;` emits `type UserId = i64;` (fully interchangeable). Generic aliases and function-type aliases work: `typedef Callback<T> = void Function(T);`.
- **Newtypes (distinct types):** `type UserId(int);` emits `pub struct UserId(pub i64);` with `.value`, derives where possible, and no arithmetic unless the user writes operators. Passing a plain `int` where a `UserId` is expected is an E0308 translated to "expected a UserId; wrap it with `UserId(5)`."
- Records and newtypes work in patterns, `@json` (newtypes serialize transparently), and `export`.
